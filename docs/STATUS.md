# airMAX Поле — состояние проекта (2026-11-14)

Android-приложение (Kotlin, Jetpack Compose) для настройки мостов Ubiquiti airMAX (airOS 6 и 8) без интернета.
Спецификация: `docs/superpowers/specs/2026-11-13-airmax-field-tool-design.md`. Планы этапов: `docs/superpowers/plans/`.

## Готово
- Этапы 1–3: подключение и статус, станции, обзор эфира, резервные копии, перезагрузка, настройки и справка.
- Этап 4: запись настроек только через резервную копию и тест-режим с автооткатом (`SafeApply`); первый вход для пушки с ubnt/ubnt; мастер моста (сторона A — AP, сторона B — станция, пара сохраняется через `pairId`); смена канала на обеих сторонах (`BothEndsOrchestrator`: дальняя 300 с, ближняя 180 с).
- Этап 5: восстановление копии через тест-режим, понятные редакторы полей (`FieldSpec`), справка по записи.
- Этап 6: ping по TCP через сеть пушки, отчёт по линку.
- По живой пушке (LiteBeam 5AC, airOS 8.7.9, дампы заказчика):
  - статус v8: оценка линка, загрузка эфира и ёмкость линка;
  - вторая сторона линка из блока `remote`;
  - обзор эфира (`scan_data`);
  - режим юстировки: стрелки «куда и на сколько градусов» по гироскопу, если телефон закреплён на антенне, и расчёт ожидаемого сигнала;
  - настройки без технических ключей, справка к каждому полю (`help/AirOsFieldHelp.kt`, `help/SettingsLayout.kt`);
  - «глазок» в полях пароля.
- Обезличенные реальные ответы пушки для тестов: `app/src/test/resources/fixtures/airos8/*lb5ac_879*`.

Тестов 168, все проходят. Последний APK: `dist/airmax-pole-stage8.apk`, версия 0.8.0 (versionCode 10).

## Не проверено на железе (главное на следующий выезд)
- **Запись конфигурации.** Адреса в `airos/WriteEndpoints.kt` угаданы: `/system.cgi` (multipart `cfgfile`) и `/apply.cgi` с testmode.
  Безопасная первая проверка: поменять «Местоположение (SNMP)», дождаться автоотката, затем «Сохранить навсегда».
- **Хеш пароля при первом входе и в мастере.** Сейчас MD5-crypt; формат не проверен.
- **Знак наклона и поворота в режиме юстировки** (`align/OrientationSensor.kt`).
- **Ключи моста** (`apply/Bridge.kt`, `BridgeKeys`) сверены с конфигурацией станции; конфигурацию точки доступа ещё не видели.

## Сборка
- Ключ подписи общий для всех сборок: `signing/airmax-pole.jks`, пароль `airmaxpole`. Новые версии ставятся поверх старых.
- На ПК (Windows, cmd):
  ```
  set "JAVA_HOME=C:\Program Files\Eclipse Adoptium\jdk-17.0.21.9-hotspot"
  gradlew.bat testDebugUnitTest assembleRelease
  ```
  Ошибка BindException лечится так: `gradlew.bat --stop`, затем `taskkill /F /IM java.exe`, затем сборка с `--no-daemon`.
- В облачной сессии нужно:
  - поставить Android SDK (cmdline-tools, `platforms;android-35`, `build-tools;34.0.0`) и прописать `sdk.dir` в `local.properties`;
  - при ошибке 429 от Maven Central подключить зеркало `maven-central.storage-download.googleapis.com` через init-скрипт Gradle.
- Каждую версию: поднять `versionCode`/`versionName` в `app/build.gradle.kts` и положить APK в `dist/`.

## Порядок работы
Работа идёт в ветке `claude/charming-ramanujan-0wc3ds`; в `main` ещё не влита.
Заказчик присылает диагностические дампы: меню ⋮ → «Сохранить диагностический дамп». В дампе ответы пушки, последний обзор эфира и конфигурация со скрытыми паролями.
Прежде чем класть реальные данные из дампа в тесты, их нужно обезличить: MAC-адреса, идентификаторы устройств, SSID.
